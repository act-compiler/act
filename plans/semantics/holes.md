# Semantic holes and rulings

Each row is a place where the spec leaves a reading open or the two generators read it differently.
A ruling either defines the behavior or rejects the program; "reject" means the front end or the issuing generator refuses it, never silent undefined behavior.

## Ruling conventions

- "Reject at issue" means every executor (oracle, simulator) refuses the issue with an error naming the instruction and the failed REQUIRE, and every producer (backend) never emits it.
- "Define" removes the row from S1.3's undefined or implementation-defined table and adds the rule to the section cited.
- A ruling that changes a generator's current output is a breaking change for the coordinated major release.
