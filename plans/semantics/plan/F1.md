# F1 Typing rules that U4 implements in the front end

## What

- Write the rules of `typing.md` and `typing-ops.md` as the reference for the TAIDL language specification, one rule per operation family.
- U4 implements them in `taidl/taidl/shapes.py`, run from `check`; F1 supplies the rule text and the accepted and rejected programs.
- A line whose written type differs from the derived one is rejected; implicit broadcast or promotion is rejected.
- The front end rejects literal dim mismatches and accepts dims equal after `fold` or with identical text; every other dim is compatible.

## Benefits

- Closes H9 and H16: both generators receive only well-typed blocks.
- Removes the "shapes not checked" rows from S1.3 and S9.

## Caveats

- Dims over `@c.` are checked by the oracle at the call and by the backend at selection, not by the front end.
- Gather and dot rules are long; copy them from StableHLO's constraints verbatim.

## Fail points

- A rule stricter than StableHLO rejects a working ISA specification; the conformance tests on `examples/` catch it.
- A rule looser than the oracle lets a disagreement through; T's cross-check catches it.

## Order and dependencies

- Depends on L (typing sections of the spec).
- Language items: L3 and U4 own the work.
- Feeds U4, T.

## Verification

- Every example under `taidl/examples` still parses.
- One rejected program per rule in T, and the oracle's call-time check agrees with the front end on every accepted one.
