# F7 Conformance suite derived from the rules

## What

- One accepted and one rejected ISA specification per rule of `typing.md` and `typing-ops.md`, and one issue per fault of `dynamics.md`, each checked to write no region and no state.
- Each test names the rule id and the hole id it closes.
- act-oracle and act-backend run the same suite; a generator that rejects a feature must cite the coverage row.

## Benefits

- Turns the rulings into executable checks; a regression in either generator fails a named test.

## Caveats

- The backend cannot execute values; its half of the suite checks acceptance, rejection, and the matched shapes.

## Fail points

- A test that encodes a generator's current output rather than the rule enshrines a bug; each test cites the spec line, not a generator.

## Order and dependencies

- Depends on F1, F2, F3, F5, T, U.
- Feeds A, D.

## Verification

- The suite passes on both generators at the v3 release, and every row of S1.3 that the rulings removed has a test.
