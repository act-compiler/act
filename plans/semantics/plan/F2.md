# F2 Region aliasing rules and the meaning of in-place marks

## What

- Each same-buffer input-output pair has one relation: tied, apart, exact-or-apart, or may overlap (panel 9, Q9.1).
- The default for an undeclared pair is exact-or-apart; pairs in different buffers need nothing (Q9.3).
- Marker expansions, over evaluated start and size terms (owner decision 34):
  - `set_inplace(k)`: same-buffer and equal-size-text checks, then `same(In k, Out)`, plus the recorded tie;
  - `set_apart(k)`: `apart(In k, Out)`;
  - `set_no_partial_overlap(k)`: `same(In k, Out) or apart(In k, Out)`;
  - `set_may_overlap(k)` (new): the empty expansion.
- Output-output pairs are apart, an implicit constraint (S1.3.5).
- A violated constraint of any source is the one fault at issue, before any write; S1.3.6 folds into S1.3.5.
- A permitted overlap gives the semantics evaluated on the pre-issue state (Q1.1 C).
- Rejected at declaration: a cross-buffer tie (owner decision 24), unequal size text on a tie, `set_apart` on identical text, identical input and output text without `set_inplace`.
- TAIDL assumes no hazard model; the ISA author declares overlap behavior (owner decision 31).

## Benefits

- Closes H1 and H2.
- One constraint list serves both generators.

## Caveats

- Breaking: an ISA specification that marks an input and an output of different buffers is rejected.
- Breaking: an unmarked partial overlap, or equal starts with unequal sizes, now faults.
- A front-end lint warns on an unmarked same-buffer pair of a non-elementwise instruction.
