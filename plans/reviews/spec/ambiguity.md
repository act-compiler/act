# Spec ambiguity review

Scope: `/home/user/taidl/docs/` S1 to S10, checked against `taidl/*.py` and the two `.g4` grammars.
Owner rulings applied: (16) no undefined behavior, each run-time violation is a defined error or a defined behavior under one norm; (17) an in-place mark is true aliasing.

## The one norm proposed for ruling 16

- Proposed S1.3 opening: "A case the front end cannot check is checked when the instruction is issued; a failed check is a fault."
- "A fault writes no region and no state variable, and the generator reports it with the instruction's name and the S1.3 row."
- "No other run-time outcome exists: every S1.3 row is a fault or a fixed result."
- Every row below that says "fault" uses this norm.

## Findings, most severe first

| Section | Sentence (short quote) | Problem | Proposed wording |
| --- | --- | --- | --- |
| S7.5 / S8.2 | "`constant` takes one literal instead: a number ... `true`; `false`; or an expression" | No rule for a literal the line's element type cannot hold, a float at an integer type, `true` at a float type, or a backtick at a float type. The generators already disagree: ACT-Backend rejects a backtick constant at a float type and rounds any float literal (`act-backend/act_backend/spec_checks.py:94-107`); TAIDL-TO accepts an integer at a float type and rejects a float literal past the type's range (`act-oracle/taidl_to/generic/utils.py:398-426`). The front end checks none of it (`taidl/operations.py:201`, `taidl/instruction.py:424` skips operands). | "At an integer type the literal is an integer literal, or a backtick expression, whose value lies in the type's range. At `pred` it is `true`, `false`, `0`, or `1`. At a float type it is any number literal or a backtick expression, rounded to nearest, ties to even; a finite value that rounds past the type's largest finite value, or `inf` at a type with no infinity, is rejected for a literal and a fault for an expression." |
| S6.2 | "A computed integer outside signed 64 bits is implementation-defined" / "A constraint whose arithmetic overflows does not hold" | Two contradictory rules in one section, plus generator-specific behavior (lines 31-32) stated as spec. With an `or`, "does not hold" can mean the whole constraint or one comparison. | "Expressions are evaluated in exact integer arithmetic, with no intermediate overflow. A start, size, shape dimension, operation attribute, or state update whose final value lies outside signed 64 bits is a fault." Delete lines 31-33. |
| S5.3 / S5.4 / S5.5 | "Constraints read the state before the instruction's updates run." | Placement marks append constraints written over starts and sizes (`taidl/instruction.py:216-218`). Those constraints read the state before updates, while the starts themselves read it after updates (S5.4 step 3), so a start over `@s.<name>` is checked at one place and accessed at another. | S5.4 step 1: "Its constraints are evaluated against the state before it, except a placement mark's constraints, which are evaluated after step 2 against the state the starts and sizes read." |
| S8.4 / S1.3 row 39 | "That reference operation gives the result's shape, its element type, and its values" | StableHLO leaves the summation order and accumulation precision of `dot` and `reduce` open, and the accuracy of transcendental functions; "leaves the result open" does not say whether these count. Two generators can disagree on every float sum. | "A float `dot` or `reduce_add` accumulates in the line's result element type, in increasing row-major order of the reduced indices, rounding each step to nearest, ties to even. A transcendental function's result is implementation-defined within 1 ulp of the exact value." |
| S8.4 | "The initial value of `reduce_<reducer>` is not yet fixed by the spec and is implementation-defined." | An open choice with no reason to stay open; "not yet" is history wording. | "The initial value is the reducer's identity: 0 for `add`, `or`, and `xor` (+0.0 for floats); 1 for `multiply`; every bit set for `and`; for `max` and `min`, -inf and +inf, or the type's lowest and greatest finite value where it has no infinity, and the integer type's least and greatest value." (This matches `act-oracle/taidl_to/generic/utils.py:439-452`.) |
| S4.3 / S5.2 | (no sentence) | The contents of a data model before its first write are never stated, so a read of an unwritten element has no meaning. | Add to S4.3: "Before the first instruction every element of every data model but `d0` is 0; `d0` holds what the generated program's caller places there." |
| S5.5 | "An in-place mark does not change what the instruction computes" / "a true flag marks an input the instruction overwrites" | Under ruling 17 the mark aliases storage, but the spec does not say which output aliases the input, or whose starts win when they differ. The front end checks neither (`taidl/instruction.py:163-172`). | "A true flag k makes output region 0 the same storage as input region k: the same data model and the same sizes, both checked by `set_inplace`, which rejects otherwise. Their starts must be equal when issued, else a fault. Because every input is read before any output is written (S5.2), aliasing never changes the computed result." |
| S1.3 row 44 / S8.4 | "The byte order `bitcast_convert` uses ..." vs "The bit layout `bitcast_convert` uses ..." | Two names for one case, and neither says how `pred` or a sub-byte type lies in `d0`. TAIDL-TO stores `pred` as one byte by `convert` and packs sub-byte types (`act-oracle/taidl_to/generic/utils.py:880-908`). | "Multi-byte values are little-endian. A sub-byte type packs 8/n elements per byte, the lowest index in the least significant bits. `pred` is one byte, 0 or 1. `bitcast_convert` follows this layout." Delete the S1.3 row. |
| S1.3 rows 35-36 / S5.2 | "A region that reaches past its data model" vs "reaches outside its data model's addressed dimensions" | "past" reads as the upper end only; a negative start is accepted (`taidl/instruction.py:136`). `d0` has no addressed dimension, so the S1.3 row never covers it. | "A region whose start is below 0, whose start plus size exceeds its addressed dimension (for `d0`, the generator's documented `d0` size), or whose size is 0 or less, is a fault." |
| S8.4 | "the StableHLO operation of S8.1, or the XLA-HLO operation where only XLA-HLO has it" | No version is named; StableHLO and XLA-HLO semantics change between releases. | "The reference is the StableHLO specification at release `<X.Y.Z>` and XLA-HLO's operation semantics at commit `<hash>`; S8.4 overrides both where it speaks." |
| S8.4 / S1.3 row 39 | "including at edge cases such as NaN, infinity, and integer overflow" | StableHLO does not fix integer `divide` or `remainder` by 0, `INT_MIN / -1`, a shift by the width or more, a negative integer `power` exponent, or a float-to-integer `convert` out of range or of NaN. | "Integer `x / 0` is -1 (every bit set); `x % 0` is `x`; `INT_MIN / -1` is `INT_MIN` and `INT_MIN % -1` is 0. A shift by the width or more gives 0, or the sign fill for `shift_right_arithmetic`. A negative integer exponent gives 0 except for bases 1 and -1. A float-to-integer `convert` truncates toward 0, saturates out of range, and maps NaN to 0." |
| S7.2 / S5.2 | "That check runs once both the semantics and the regions are given, in either order." | If `set_inputs` or `set_outputs` is never called, no check runs (`taidl/instruction.py:99-100`, `254-257`); regions with no semantics are never checked either. | "Every instruction gives `add_semantics`, `set_inputs`, and `set_outputs`, or none of them; a generator rejects an accelerator whose instruction gives some but not all." | S7.4 | "A shape lists dimensions between brackets, each an integer or an expression in backticks." | Dimension 0 is accepted by `dim : INT` (`IDLV2.g4:23`); a backtick dimension may be 0 or negative; neither is in S1.3. | "Each dimension is at least 1; a literal 0 is rejected, and a backtick dimension below 1 is a fault." |
| S7.2 / S1.3 rows 38, 40 | "A region value with another element count, or another element type ... is ... undefined" | Under ruling 16 these must be errors, but shapes with backticks are known only at issue. | "The front end rejects a mismatch between literal shapes; a mismatch that depends on a backtick expression is a fault." | S4.4 / S1.3 row 46 | "An initial value outside signed 64 bits is undefined; the front end does not reject it." | Statically checkable (`taidl/accelerator.py:69` checks the type only). | "An initial value outside signed 64 bits is rejected with `ValueError`." Move to S9. |
| S6.3 | "A condition is one or more comparisons joined by `and` and `or`" | Short-circuit order is unstated, so a fault in an arm that need not be evaluated may or may not occur. | "Every comparison of a condition is evaluated, left to right; a fault in any of them is a fault of the constraint." |

| S2.1 | "`INT` ... unsigned; leading zeros allowed" | Base is unstated; a C generator reading `010` with `strtol(..., 0)` gets 8. | "`INT` is decimal; leading zeros do not change its value." |

## Grammar page against the .g4 files

- S3.2 omits `compare : EQ | NE | LT | LE | GT | GE ;` (`taidl/antlr4/IDLV2Expr.g4:25`); every other parser rule of both grammars matches S3.1 and S3.2 exactly.
- S2.2 never states longest-match and earlier-rule-wins for expression tokens, and lists no `WS` row (`IDLV2Expr.g4:62`); add both, as S2.1 has them.

## Missing S1.3 entries (accepted by the front end, meaning not given)

- A data model declared after an instruction (`taidl/accelerator.py:47-58`; listed only under S9 "not rejected").
- An instruction with semantics but no `set_inputs` or `set_outputs`, or with regions but no semantics (`taidl/instruction.py:99-100`, `109-110`, `254-257`).
- A shape dimension of 0, or a backtick dimension below 1 (`taidl/antlr4/IDLV2.g4:23`; `taidl/instruction.py:419-437` checks only 64 bits).
- A `constant` literal outside its element type, of the wrong kind, or past 64 bits (`taidl/operations.py:201`; `taidl/instruction.py:424` skips operands).
- A negative start, and any `d0` region past the generator's `d0` size (`taidl/instruction.py:136` parses `str(-1)`).
- The contents of a data model before its first write (no line of the spec or front end).
- The summation order and accumulation type of a float `dot` or `reduce_*` (S8.4 only).
- Integer `divide` or `remainder` by 0, `INT_MIN / -1`, shifts by the width or more, negative integer `power`, float-to-integer `convert` out of range.
- `inf` at a type with no infinity (`f8e4m3fn`), and the NaN bit pattern; TAIDL-TO rejects the first (`act-oracle/taidl_to/generic/utils.py:411`).
- Whether an `and` or `or` arm is evaluated when the other decides the condition.
- A flag of `set_inplace`, `set_apart`, or `set_no_partial_overlap` that is not a `bool`; truthiness is used (`taidl/instruction.py:168`, `203`).

## Missing S9 entries (rejected by the front end, absent from S9)

- A semantics with no `%Out<k>` line: `SyntaxError` from `add_semantics`, since `ROOT` must sit on `%Out0` (`taidl/instruction.py:311-318`).
- A start or size that is neither an `int` nor a `str`, such as `1.0` or `True`: `SyntaxError` from `set_inputs` or `set_outputs`, via its `str` text (`taidl/instruction.py:136-137`).
- A start or size given as a Python `int` outside signed 64 bits: `SyntaxError`, by the literal check (`taidl/instruction.py:408`); the Texts row names only texts.
- A `%In<k>` or `%Out<k>` spelled with a leading zero, such as `%In01`: `SyntaxError` as a value with no region (`taidl/instruction.py:150-161`); worth a row so generators do not read it as `%In1`.
- A name that is not a `str`: `ValueError` (`taidl/names.py:9`); the Declarations row says "not an ASCII identifier" only.
- A list entry that is not a `str` in `add_instruction` or `add_constraints`: `strings` does not check entries, so the error, if any, comes from the parser or `check_name`, not a defined `TypeError` (`taidl/instruction.py:452-456`, `taidl/names.py:9`).
