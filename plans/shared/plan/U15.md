# U15 Toolchain pin set

- What: one released StableHLO version is the pin (for example tag v1.20.0); its LLVM commit is read from the tag's `build_tools/llvm_version.txt` and never written in a public build file (owner decision 33, Q12.4).
- What: one build image holds the MLIR and StableHLO static libraries at that pin, with a CI cache, beside U9's docker and CI scripts.
- What: public users receive a prebuilt importer (B47); a public source build that must fetch LLVM reads the commit from the StableHLO tag, else the source build stays in the private repos.
- What: producers of StableHLO (torch-mlir, jax) run in their own package and process and hand over a portable artifact at this version; their MLIR never links into ACT.
- Benefits: B47, B48, O34, and O36 build against one MLIR, and a release pins a released version only.
- Caveats: StableHLO releases weekly, so a pin bump is a deliberate step with a CI run; MLIR has no stable C++ API, so every MLIR consumer moves together.
- Fail points: a consumer built against another LLVM; noticed by a CI check that each MLIR library's commit equals the tag's `llvm_version.txt`.
- Order and dependencies: after U9; A16 records the pin in the release checklist.
- Verification: the image builds from the tag alone; B47 and O34 link against its libraries; no public file names an LLVM commit.
- Breaking: no.
