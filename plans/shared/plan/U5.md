- What: `TYPES` (taidl/taidl/data_model.py:4-24) becomes one table with width, signedness, float bits and integer range.
- What: a front-end `literal_fits(text, type)` from act-oracle/taidl_to/generic/utils.py:380-436, called for `constant` lines and state values.
- What: the backend's `reads_as` (act-backend/act_backend/spec_checks.py:94-107) and `ELEMENT_TYPES` (act-backend/act_backend/isel_ir2isa_rewrites_rs_generator.py:23-37) read the table; a test checks the Rust `Dtype` variants (act-backend/act_backend/generic/src/ir/dtype.rs:2-16) against it.
- What: the Rust literal parse rounds once (X8).
- Benefits: closes X6 and X8; one list of types for six tables in three languages.
- Caveats: float range at `f8e4m3fn` has no infinity and needs the oracle's `float_largest` logic.
- Fail points: drift between the Rust enum and the table; noticed by the test.
- Order and dependencies: after U2; with L16, O8.
- Contract: `literal_fits` is a listed contract function (U3); the backend and the oracle call it instead of keeping a copy.
- Verification: per-type corpus entries at each range edge get one verdict from both generators.
