# U11 Adding a generator: template generator and expectations

- What: a documented path for a new generator such as act-allo (decision 39), whose guide is the generator guide in the `taidl` docs (S12.4, text by L41) and whose code is a template generator in `act/examples/generator_template/`.
- What: the template is L41's worked generator; there is one worked generator, and A27 refers to L41 for it.
- What: the template entry takes a `Model` or an `Accelerator` and reads only the `Model` that `check` returns (U2, U10), exposes `generate_template(source, /, base_dir=None, **options)`, writes one text file per instruction under `<base_dir>/accelerators/<accelerator>/template/`, and returns the frozen report (U2).
- What: it owns the metadata namespace `template`, rejects an unknown key in it naming node and key (a plain function run after `check`), ignores every other namespace, and reports the namespaces it read.
- What: an instruction the template cannot model is excluded with a printed reason, never rejected (B46 is the worked case).
- What: it ships an expectations table (T11) with one row per corpus case, `supported` or `unsupported` with a coded reason, and `coverage.md` generated from it.
- What: it joins the T12 runner and the T35 neutrality run: the oracle's and the backend's output stay identical with its metadata stripped.
- What: it follows the failure policy (decision 40): it rejects only a problem the architect can correct, with a coded error naming the clause (D16).
- What: it registers no check beyond its own functions and subclasses nothing (U10).
- What: the steps to copy are numbered in the generator guide in the `taidl` docs (S12.4): copy the package, rename `template`, replace the emitter, fill the expectations table, run the runner.
- Benefits: a new generator lands without touching `taidl`, the oracle, or the backend, and its corpus expectations are the acceptance test.
- Caveats: the template is a worked example and ships no accelerator; it changes with `CONTRACT_VERSION`.
- Fail points: a template that drifts from the contract; its own tests run in the `act` CI against the pinned taidl.
- Order and dependencies: after U2, U3, U10, T11, T12; with L40 and L41; Q2.
- Verification: a clean checkout copies the template, renames it, and passes T12 and T35 without a change outside the new package.
- Breaking: no.
