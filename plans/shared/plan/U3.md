# U3 The check function

- What: `taidl.check(acc)` runs every front-end rule once, after the ISA specification is built, freezes the accelerator, and returns a `Model` (Q11.3).
- What: it collects every problem and raises one `Rejection`; each entry carries the code, the section id, the instruction, and the author's file and line (Q3.8 form, D2).
- What: it is the standalone check of decision 42: `python -m taidl check spec.py` prints the entries and exits 1 on a rejection.
- What: a trace-time error, such as `if` on a symbolic value, is a Python exception at the author's line and stops at once; `check` never sees it (U12).
- What: it checks each written value's element type against its buffer and its element count against its region where literal (X3, X4; taidl/docs/semantics.md:47), and each read the same way, so no generator patches the gap the oracle patches today (act-oracle/taidl_to/semantic_generator.py:36-40).
- What: the `Model` carries typed members: per-line result type and dims (folded expressions over `@c.` where `fold` applies), folded sizes, the value-to-region map, and the call site of each node.
- What: those members are fields of the frozen `Model`, so none exists before `check` has run; there is no silent default.
- What: `fold` and `literal_fits` are listed contract functions; the shape-rule functions are not.
- Benefits: one accepted set for both generators on S7.2; generators stop re-deriving shapes and the backend regex scan (act-backend/act_backend/isel_ir2isa_rewrites_rs_generator.py:91, :134-137); an outside generator gets the call site for line 2 of a `U` message.
- Benefits: an architect fixes five typos in one run.
- Caveats: an expression-sized region needs a symbolic or per-call check; the front end checks literals and leaves the rest to the oracle's call-time check.
- Fail points: a valid example rejected; noticed by running every example in the three repos and the corpus of U7.
- Order and dependencies: after U2, L5; before U10 and U12.
- Verification: corpus entries for type mismatch, fewer elements and more elements are refused by the front end with one coded message; a specification with five faults gives one `Rejection` with five entries; a generator given an `Accelerator` and one given its `Model` produce identical output.
