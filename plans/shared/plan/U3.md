# U3 One final validation that publishes derived facts

- What: `Accelerator.validate()` runs every whole-description check once, after all calls.
- What: it checks each region value's element type against its data model and its element count against its region where literal (X3, X4; taidl/docs/semantics.md:47).
- What: it checks every `%In<k>` and `%Out<k>` against its region even when `set_inputs` never ran, the gap act-oracle/taidl_to/semantic_generator.py:36-40 patches today.
- What: it attaches typed members: per-line result type and dims (folded expressions over `@c.` where `fold` applies), folded sizes, the value-to-region map, and the call site of each `add_*` and `set_*` call.
- What: each such member raises when read before `validate()` has run; there is no silent default.
- What: `fold` and `literal_fits` are listed contract functions; the shape-rule functions are not.
- Benefits: one accepted set for both generators on S7.2; generators stop re-deriving shapes and the backend regex scan (act-backend/act_backend/isel_ir2isa_rewrites_rs_generator.py:91, :134-137); an outside generator gets the call site for line 2 of a `U` message.
- Caveats: an expression-sized region needs a symbolic or per-call check; the front end checks literals and leaves the rest to the oracle's call-time check.
- Fail points: a valid example rejected; noticed by running every example in the three repos and the corpus of U7.
- Order and dependencies: after U2, L5; before U10.
- Verification: corpus entries for type mismatch, fewer elements and more elements are refused by the front end with one coded message; reading a derived member before `validate()` raises.
