# U13 Converter and equivalence tests

- What: a converter script on the taidl 2.x line, run under taidl 2.x; it is not a `taidl` subcommand.
- What: it reads loaded v2 `Instruction` objects (`instr_input_asts`, `constraint_asts`, `instr_semantics_ast`; taidl/taidl/instruction.py:44-55) and prints the surface of U12.
- What: it runs once on the corpus: 25 Python files in taidl, act-oracle, and act-backend, and 7 under act (tutorials and `tests/test_end_to_end.py`); the converted files are committed.
- What: one equivalence test per corpus file: the `Model` built from the v2 string form equals the `Model` traced from the converted file, up to call sites.
- What: a test that assembles semantics text at run time is rewritten by hand from the printer's output.
- What: the v3 removed-names rejection of `add_semantics` names the converter and the 2.x line (D15).
- Benefits: no dual acceptance of two surfaces; the equivalence test checks the contract itself.
- Caveats: no `taidl migrate` command ships, since no plan names an outside owner of a v2 ISA specification; a release can wrap the script later.
- Caveats: the tree-to-`Model` builder written for U2 and U3 is the converter's front half and the equivalence oracle.
- Fail points: a construct the visitor prints with another meaning; noticed by the equivalence test on the file that uses it.
- Order and dependencies: after U12 and U10; before U14.
- Verification: every corpus file converts and passes its equivalence test; the run-time-assembled tests pass on the printer-derived text.
